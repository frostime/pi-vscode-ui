# Conversation Markdown Rendering

- Ordinary Markdown uses `markdown-it` with raw HTML disabled, then sanitizes output. Mermaid uses strict security, sanitizes SVG, and fails closed without injecting raw output.
- Rendered content has no network channel. Mermaid draws into the live document before its output can be sanitized, so the document's Content Security Policy is the control: no product may grant a remote image, font, style, frame or connection source. As a second layer, the sanitizer removes resource references from the stored SVG: URL attributes other than link targets, every `srcset` and `ping`, and external `url()`, `image-set()` and `@import` in the diagram's style sheet, inline styles and presentation attributes. Same-document fragments and inline `data:` stay, and a style sheet that hides a reference behind escapes or comments fails the diagram. A style sheet inside a label is removed, not edited: HTML serializes its text raw, so only the SVG-namespace sheet may be rewritten after sanitization. These patterns run on text the message chooses and must stay linear in its length. External diagram links use the same confirmed host action as other chat links.
- Markdown images that reference remote URLs or local files render as placeholders. Remote placeholders show the host. For a local image, use Pi’s read tool so the file follows the session’s permissions. Tool screenshots, read results and uploaded images display the bytes already supplied to the conversation.
- Embedded Markdown images support PNG, JPEG, WebP, GIF, AVIF, BMP and SVG data. Malformed image data fails through the browser decoder. SVG images have script elements removed before becoming Blob URLs and show a warning if scripts were removed. SVG images are never injected into the rendered Markdown DOM. These formats do not change the separate prompt-attachment formats.
- Markdown images preserve aspect ratio, do not upscale, fit within 92% of the message width and a 640px maximum, and use `min(400px, 55vh)` as their transcript height bound. An explicit Markdown title is a centered caption without surrounding card chrome. When no title is present, concise alt text (up to 160 Unicode characters) is used as the caption; long alt text remains only the accessible/failure description. Unlinked loaded images open the shared Lightbox, while linked images retain link behavior.
- Explicit Markdown file links and whitelisted inline-code references open through validated `openFile`; supported locations include line, column, line-range, and GitHub `#L` forms. Both products resolve a missing path through one shared best-effort workspace search (the reference as written, its basename for a stale absolute path) and apply the host's line/column targeting; with no match, the host's own missing-target behavior applies. In VS Code, content that cannot open as a text document falls back to the default `vscode.open` viewer without location targeting. Desktop's whitelist, external-editor/default-application routing and its own missing-target rules belong to `apps/desktop/SPEC.md`. When the product does not provide file-reference navigation, references remain readable but cannot trigger `openFile`; they do not retain misleading link styling. A file click handled by FrostPi stops at the message so the VS Code webview frame cannot also route it.
- Chat links to HTTP(S) URLs render without a browser navigation target. A click or Enter sends the exact destination to the host for a one-time confirmation. The dialog shows the full URL and explains that the browser may bypass network restrictions if Pi runs in a sandbox. Bare URLs and diagram links follow this rule. Other external schemes and URLs with credentials have no open action. Hover and keyboard focus reveal a URL locally.
- Resting over a link for one second shows its target in one fixed tooltip shared by every mounted message; keyboard focus shows the same label immediately. A file reference resolves against the displayed Session cwd and appends its line, column, and range; parent segments cannot escape a Windows drive or UNC share root, and POSIX backslashes remain filename characters. An HTTP(S) link shows its full URL. The tooltip stays within the horizontal viewport and appears above its link when it fits there but not below. It labels the navigation target, not the host's resolved path, and retires on scroll, resize, pointer leave, when the hosting message replaces its markup, or when that message unmounts. One global scroll/resize listener pair serves the shared tooltip; the last message unmount removes those listeners and the tooltip element.
- Incomplete Mermaid fences remain source text while streaming; only complete fences mount a diagram, and render failure shows the error plus original source.
- Fenced code blocks get a hover/focus action group (injected by `MarkdownHtml.svelte`, not part of sanitized HTML). Copy sends the block's raw code text through `copyText` and confirms in place briefly. Wrap toggles soft wrapping for that block only, exposes its state through `aria-pressed`, and preserves an explicit choice across re-renders of the mounted message.
- Fence chrome: the outer `pre` clips and hosts the hover chrome; the inner `.code-scroll` scrolls. Prose-like languages (`txt`, `text`, `plaintext`, `md`, `markdown`, `tex`, `latex`) wrap by default and therefore start with Wrap active; other and untagged fences start unwrapped. Either default can be toggled per block. While the code block is neither hovered nor focused within, its action group ignores pointer events; hovering or focusing within the block reveals the actions and restores pointer interaction.
- `diff` and `patch` fences use VS Code Diff theme colors for full-line additions and deletions. Adjacent deletion/addition runs are compared as word-token streams (Latin words, single CJK characters, punctuation, whitespace), so one line can carry several separate emphasized ranges and the runs need not have equal sizes. Lines whose emphasis would cover most visible text fall back to whole-line highlighting, and oversized blocks skip intra-line emphasis. Recognized tool-result diffs share this classification and emphasis model while retaining their compact tool-card chrome.
- Copy uses original protocol text in order, never rendered HTML, SVG, math markup, images, reasoning, tools, or notices.
