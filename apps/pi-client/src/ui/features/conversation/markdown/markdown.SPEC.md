# Conversation Markdown Rendering

- Ordinary Markdown uses `markdown-it` with raw HTML disabled, then sanitizes output. Mermaid uses strict security, sanitizes SVG, and fails closed without injecting raw output.
- Rendered content has no network channel. Mermaid draws into the live document before its output can be sanitized, so the document's Content Security Policy is the control: no product may grant a remote image, font, style, frame or connection source. As a second layer, the sanitizer removes resource references from the stored SVG: URL attributes other than link targets, every `srcset` and `ping`, and external `url()`, `image-set()` and `@import` in the diagram's style sheet, inline styles and presentation attributes. Same-document fragments and inline `data:` stay, and a style sheet that hides a reference behind escapes or comments fails the diagram. A style sheet inside a label is removed, not edited: HTML serializes its text raw, so only the SVG-namespace sheet may be rewritten after sanitization. These patterns run on text the message chooses and must stay linear in its length. A link in a diagram may leave the document only through an explicit click.
- Markdown image syntax renders an inert sanitized placeholder before any source is activated. Relative paths resolve from the displayed Session cwd; absolute paths and `file:` URIs refer to the Extension Host filesystem. Local and supported `data:` images load automatically near the viewport. An HTTPS image stays a placeholder naming its host until an explicit `Load image` action; the Host then fetches it and the Webview shows the returned bytes, never the URL. That request is HTTPS-only including every redirect, carries no credentials, cookies or referrer, follows the current workspace proxy policy without falling back to a direct connection, and is bounded by a deadline and the attachment byte limit. HTTP and other schemes remain blocked. On Windows, a local source that names a network share (`\\server\share`, `//server/share`, `file://server/…`) is refused before any filesystem access unless the Session's own working directory is on that same share, and a device-namespace path (`\\?\…`, `\\.\…`) is always refused.
- Conversation images support PNG, JPEG, WebP, GIF, AVIF, BMP, and SVG from local files, supported `data:` sources, or explicit HTTPS loads. Host-loaded images are bounded by the configured attachment byte limit and identified by their bytes; malformed image data fails through the browser image decoder. SVG images have `<script>` elements removed before becoming Blob URLs; if scripts were removed, the image shows a warning. SVG is never injected into the rendered Markdown DOM. This display-format list does not change the separate prompt-attachment formats.
- Markdown images preserve aspect ratio, do not upscale, fit within 92% of the message width and a 640px maximum, and use `min(400px, 55vh)` as their transcript height bound. An explicit Markdown title is a centered caption without surrounding card chrome. When no title is present, concise alt text (up to 160 Unicode characters) is used as the caption; long alt text remains only the accessible/failure description. Unlinked loaded images open the shared Lightbox, while linked images retain link behavior.
- Explicit Markdown file links and whitelisted inline-code references open through validated `openFile`; supported locations include line, column, line-range, and GitHub `#L` forms. Both products resolve a missing path through one shared best-effort workspace search (the reference as written, its basename for a stale absolute path) and apply the host's line/column targeting; with no match, the host's own missing-target behavior applies. In VS Code, content that cannot open as a text document falls back to the default `vscode.open` viewer without location targeting. Desktop's whitelist, external-editor/default-application routing and its own missing-target rules belong to `apps/desktop/SPEC.md`. When the product does not provide file-reference navigation, references remain readable but cannot trigger `openFile`; they do not retain misleading link styling. HTTP(S) remains external and opens only through `openExternal`, subject to the host's own confirmation for external links. A click FrostPi routes, file or HTTP(S), stops at the message: VS Code's webview frame sends every anchor click that reaches its window to its own opener, ignoring `defaultPrevented`, which would open the page a second way, without waiting for that confirmation, or scroll the frame to the top for `href="#"`. Right-clicking a link the tooltip below would label hands that label to VS Code's webview context menu as `data-vscode-context`, resolved when the menu opens (sections and key in `src/shared/model/linkContextMenu.ts`): **Copy Link Address** for HTTP(S), **Copy Path** for a file reference, entries the VS Code manifest contributes under `webview/context`. The attribute is inert in Desktop.
- Resting over a link for one second shows its target in one fixed tooltip shared by every mounted message; keyboard focus shows the same label immediately. A file reference resolves against the displayed Session cwd and appends its line, column, and range; parent segments cannot escape a Windows drive or UNC share root, and POSIX backslashes remain filename characters. An HTTP(S) link shows its full URL. The tooltip stays within the horizontal viewport and appears above its link when it fits there but not below. It labels the navigation target, not the host's resolved path, and retires on scroll, resize, pointer leave, when the hosting message replaces its markup, or when that message unmounts. One global scroll/resize listener pair serves the shared tooltip; the last message unmount removes those listeners and the tooltip element.
- Incomplete Mermaid fences remain source text while streaming; only complete fences mount a diagram, and render failure shows the error plus original source.
- Fenced code blocks get a hover/focus action group (injected by `MarkdownHtml.svelte`, not part of sanitized HTML). Copy sends the block's raw code text through `copyText` and confirms in place briefly. Wrap toggles soft wrapping for that block only, exposes its state through `aria-pressed`, and preserves an explicit choice across re-renders of the mounted message.
- Fence chrome: the outer `pre` clips and hosts the hover chrome; the inner `.code-scroll` scrolls. Prose-like languages (`txt`, `text`, `plaintext`, `md`, `markdown`, `tex`, `latex`) wrap by default and therefore start with Wrap active; other and untagged fences start unwrapped. Either default can be toggled per block. While the code block is neither hovered nor focused within, its action group ignores pointer events; hovering or focusing within the block reveals the actions and restores pointer interaction.
- `diff` and `patch` fences use VS Code Diff theme colors for full-line additions and deletions. Adjacent deletion/addition runs are compared as word-token streams (Latin words, single CJK characters, punctuation, whitespace), so one line can carry several separate emphasized ranges and the runs need not have equal sizes. Lines whose emphasis would cover most visible text fall back to whole-line highlighting, and oversized blocks skip intra-line emphasis. Recognized tool-result diffs share this classification and emphasis model while retaining their compact tool-card chrome.
- Copy uses original protocol text in order, never rendered HTML, SVG, math markup, images, reasoning, tools, or notices.
