# Composer contract

The Composer is a plain-text CodeMirror editor. FrostPi submits exactly the visible document text plus explicit image attachments; IME, selection, undo/redo, clipboard, and multiline editing remain native.

The containing shell supplies local-command completion/handling and whether rejected submissions are restored locally. A handled command declares its draft transition (keep, clear, or replace text); Composer applies that transition before invoking the host action. Sidebar and Panel adapters preserve the command and recovery rules below without asking Composer to infer them from a surface name. The product chooses its local/runtime command list once; PromptEditor consumes that list without adding commands again. Product-only registrations must not suppress a same-named Pi command in another product. Draft authority remains a separate input; it is not replaced by the local-recovery flag.

- `Enter` inserts a newline and continues/removes Markdown `-`/`*` list markers. `Tab` accepts completion or indents by two spaces; `Shift+Tab` removes up to two spaces or one tab without moving focus.
- `Ctrl+Enter` and `Cmd+Enter` submit with the session's current streaming delivery; `Alt+Enter` explicitly uses Queue without changing that selection. While idle, both start a normal prompt.
- Idle Composer chrome keeps the existing single Send action. While streaming, Stop remains fixed at the right edge; a non-empty draft reveals an adjacent split Send action whose menu selects Steer or Queue. The selection is remembered per session for the current Webview lifetime and initializes from `frostpi.composer.streamingBehavior`.
- An ordinary Sidebar Composer remains Webview-local. Opening a Session Tab transfers its complete text/images into the Host's transient handoff cache; while externalized, mutations synchronize immediately with monotonically increasing revisions, replacements are never merged, and Host replacements do not echo. Submission clears immediately. The Host retains the failure snapshot for an externalized Composer, while the Sidebar retains it locally; a failed correlated result restores it only when no newer draft exists, and success never overwrites later Host/editor text. Request identifiers must remain available when `crypto.randomUUID` is unavailable. Prompts accepted while streaming remain visible as Steer or Queue bubbles until Pi injects them.
- Restore all applies recovered content once, before the latest draft with blank-line separators; it preserves existing attachments and never sends or reconstructs per-message delivery types. Host-applied results must not be merged again by the browser. From the recovery request until its result is applied or fails, the originating Composer is read-only: text changes, attachment additions/removals, sending and Sidebar→tab externalization wait. Locking begins before the request is posted, so earlier immediate Host draft mutations precede recovery. Other Sessions remain editable; agent execution and Stop are not locked. A pending submission also blocks Restore all so its cleared draft cannot race recovery; this UI restriction is per Session.
- Recovery results use the application's existing auto-expiring toast, never a persistent Composer notice or a separate notification lifecycle. Correlated duplicate/stale replies produce no extra feedback.
- Pi recovery is text-only best effort: pending images disable the operation, compaction disables it at both UI and Runtime boundaries, and feedback briefly warns that the original messages may still run, without explaining submission or delivery internals. OMP restores confirmed removals and available returned images; missing/over-capacity images and unconfirmed results are explicit partial outcomes. Do not add per-message confirmation states or imply empty bubbles prove cancellation. Closing a Host-owned tab during recovery follows the bridge's draft-ownership window.
- Text is trimmed before Host handling. Unicode whitespace between a leading slash command and its arguments is normalized to one ASCII space; the runtime parses the remaining arguments.
- OMP completion exposes only supported Markdown commands and skills. The Host also validates manually typed leading slash invocations before dispatch. Live user bubbles retain the original invocation; there is no expanded-command preview. OMP skill/image submissions fail explicitly. Separate OMP `prompts/` templates and builtin/extension/custom/MCP runtime commands are not part of this surface; Host-local actions retain their own paths.
- Text-only `/compact` delegates to Pi's compact request, takes precedence over a same-named extension command, and never appends a user prompt. `/resume` is also Host-local; FrostPi's `/editor` registration belongs to the VS Code product. Session Tabs omit `/resume` completion and reject explicit `/resume` with guidance to use the sidebar.
- `/clear`, `/rewind` and `/btw` are Host commands like `/compact`: text-only, never appended as a user prompt, never a queued Steer or follow-up, and they win over a same-named Pi extension command or prompt template. Unlike `/compact` they depend on the runtime, so they are not in a product's static list: the Host adds each to a Session's own command list only when that Session's runtime profile and bundled adapters support it. An adapter counts as present until the Pi process's own command list shows it did not load; a command list that failed to load proves nothing. Where a command is not supported, it is neither offered nor intercepted, and its text reaches the runtime as typed. `/clear` and `/rewind` take no argument, so text after either is submitted to Pi unchanged; `/btw` requires a question. A refused Host command is an ordinary failed submission and restores the draft. `/rewind` hands the chosen prompt back through the Composer seed contract, so that seed must survive the `/rewind` submission that produced it. What each command does to the Session is in the [lifecycle contract](../../../host/session-lifecycle.SPEC.md#host-commands-on-the-conversation).
- VS Code's `/editor` allows one temporary Markdown file at a time across all presentations. Closing its tab replaces the owning Session's cached text while preserving attachments; another `/editor` reveals the existing tab.
- The expanded Composer remains local to one Webview presentation. It stays expanded across updates to the displayed Session and collapses only on displayed-Session switch, explicit minimize, or Escape. Scroll, disclosure, expansion, and partially entered Question/extension-form answers are not handed between sidebar and tab.
- File mentions insert only path/line text. FrostPi never reads or injects referenced file content.
- PNG/JPEG/WebP attachments remain explicit and obey prompt validation limits.
- Fork preserves the original session draft and delivers selected text/images to the new temporary session through a Host-validated, one-shot, non-persisted seed.
- In-place tree navigation uses the same seed contract under the same session id; replacing a non-empty draft requires Host confirmation, and non-editable targets preserve it.
