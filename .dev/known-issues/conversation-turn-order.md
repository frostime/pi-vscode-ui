# 上一轮历史晚到时，会话消息可能短暂倒序

**状态：暂缓修复。** 这是共享会话投影中的旧问题，在 `main`（`v0.16.7`）已存在，最早见于 `79bf3c78`。PR #13 的忙时 Fork 测试暴露了它，但触发不需要 Fork。

**触发条件：** 下一轮 B 已进入 FrostPi 的实时会话列表，此时才应用一批包含上一轮 A、但尚不包含 B 的历史条目。`apps/pi-client/src/core/conversation/ConversationProjection.ts` 给 A 补上 Pi 历史 ID 时调用 `replaceTurnAtEnd`，把 A 移到 B 后面。如果同一批也回填 B，批处理结束时不会留下这次倒序。后续回填 B 可恢复顺序；未发现 Pi 保存的历史被改乱。

**证据与搁置依据：** 在 `6b32c04` 上用真实 Pi 1.5.2 和本地模拟模型响应复现。三次倒序的样本中，B 在上一轮结束后约 2–4 毫秒插入，倒序的 Host 状态约 150 毫秒后恢复。另做了 40 次连续发送对照，均未倒序。这些数字是本机样本，不是触发阈值。尚未验证真实 VS Code 是否绘制出倒序，也未确认手动操作中的频率。遇到同样的短暂倒序可先搁置；若普通操作可反复触发、顺序持续错误，或磁盘历史受影响，再重新评估。

**测试边界：** `apps/pi-client/test/host/sessionCommands.test.ts` 中的忙时 Fork 回归应在发送下一条测试消息前，确认要 Fork 的消息已有 `sourceEntryId`。这只是测试前置条件，不修复倒序，也不意味着可以放宽 Fork 断言。
