# Desktop MSI 安装与分阶段更新

本文以本轮用户确认的“最小实现 + Fail Loud”为准，取代此前增加的安全审计、恢复和构建证明要求。实现边界见 [SHAPE](desktop-msi-updates.SHAPE.md)，待办与验证状态见 [PLAN](desktop-msi-updates.PLAN.md)。用户已授权合并到 `quasi-main`，不包含 tag、推送或发布。

## 最小完成目标

跑通一次 `Settings → 检查 → 下载到本地 → 安装 → 自动重开` 的正常更新。

1. 生成全用户 Windows x64 MSI，包含匹配的 EXE、Node 后端、Pi 扩展及运行资源；接受 UAC。
2. 现有 Settings 内分别提供检查、下载、安装。更新操作不依赖设置 Save，也不绕过现有未保存修改保护。
3. 有 Session 时仍可检查、下载；下载完成不自动安装或退出。
4. 保存一份完成的本地下载和必要版本信息，跨重启仍可安装。安装明确使用该本地版本，不重新下载、不请求 latest；后来检查到其他版本不改变安装对象。
5. 当前 Desktop 所有 Project 的打开 Session 均阻止安装，包括 stopped、后台及等待输入的 Session。历史文件不算打开的 Session。用户自行关闭，不提供隐式批量关闭。
6. Node 后端执行最终门禁；未完成的 New/Resume 也阻止安装。获准安装后不再接纳新 Session，避免退出时终止刚创建的任务。
7. 正常保存 Desktop/Registry 元数据后，使用官方 updater/MSI 安装并退出。保存失败不得启动 MSI；成功升级后自动重开同一个数据 profile。
8. profile 只支持绝对 Windows 路径。相对路径启动时明确报错、非零退出，不猜基准、不修正、不回退。
9. 程序更新不删除设置、Project/Session 索引或 Pi 历史。保留既有 ZIP 交付，不扩展为运行时、Pi 或数据格式升级。
10. GitHub Release 提供 MSI、官方工具所需签名及版本清单；先上传安装资产，再公布清单。产品版本仍来自 `apps/vscode/package.json`。

## 实现范式

只写明确要求的正常路径。内部调用方可信；来自网络、文件、用户输入和子进程的数据在入口校验，错误指出输入、实际值和违反的约束。不得用默认值、猜测或兼容分支掩盖错误。

持久化必须原子写入或使用事务，不能因删减代码而暴露半成品。正常执行中发生错误即停止并明确报错；失败不继续依赖成功结果的步骤，不伪报成功，不主动删除用户数据。允许操作失败、重启或重新下载，不写自动修复、重试、回滚或脏数据清理。catch 仅用于释放资源、补充上下文后重抛，或进程顶层打印并非零退出。

“安全”指避免实质性损伤，不是让所有异常都继续可用。优先禁止不支持的操作，要求用户正确操作，不为平滑体验设计恢复机制。

## 责任边界

- Node 拥有完整 Session 集合与准入；Rust 拥有本地更新文件及官方 updater 调用。renderer 仅使用有限操作，不获得任意 URL、路径、命令或原生 updater 权限。
- 复用现有元数据收尾顺序；不能依赖官方 updater 的同步退出回调完成异步保存。MSI 从 Rust 启动，不放进 Node 的 kill-on-close 进程树。
- 不改共享 ClientApp、Registry 或 Pi RPC 的执行职责，不全局串行 agent turns，不增加 VS Code 开发的 Rust/MSI 前提。
- 官方工具自带行为沿用，但不由此衍生 FrostPi 的额外保证。污染、攻击或篡改安装包不属于本次承诺。
- 不做逐文件 hash 账本、构建来源档案、手写签名/Key-ID/签名注释审计、额外文件头检查、进程扫描、跨实例锁或多 profile 更新协调。
- 不做自动恢复/回滚、取消后恢复运行、失败时保住旧下载的额外事务承诺、多版本缓存、断点续传、自动检查/下载或常驻更新服务。原子持久化要求仍保留。

## 完成验收

| 场景 | 必须观察到的结果 |
|---|---|
| 任一 Project 有打开的 Session | 可检查、下载；后端拒绝安装；检查/下载不打断 Session |
| 全部 Session 关闭，且无未完成 New/Resume | 可获准安装；获准后不能创建新 Session |
| 下载后重启并断网 | 仍安装本地显示的那个版本，不请求 latest、不重新下载 |
| 相对 profile 或正常执行遇到错误 | 明确拒绝/报错；不静默回退、不谎报成功 |
| 首次 MSI 安装（用户已验证） | 安装完成，应用能运行 |
| 后续 MSI → MSI 升级（不阻塞本次合并） | 数据保留；应用自动重开原 profile 且可用 |

此前发行版只有 ZIP，没有已发行的旧版 MSI。用户已确认首次 MSI 安装后能运行，并接受本次合并；内置安装、后续 MSI → MSI 升级及自动重开仍未实测。后续验证使用隔离的安装目录和测试 profile。污染包、取消恢复、异常回滚和审计报告不是完成条件。
