# Desktop MSI 安装与分阶段更新

本文记录本次变更的用户目标与约束；[SHAPE](desktop-msi-updates.SHAPE.md) 描述候选实现和待验证边界。文档处于待评审状态，尚未开始实现，也不代表授权发布。

## 背景与已确认的方向

当前 Desktop 发布 Windows x64 便携 ZIP，需要用户下载、解压并手工替换程序。程序由 Rust/Tauri 壳、Node 后端和随包 Pi 扩展组成，不能只更新 EXE。设置、Project/Session 索引和 Pi 历史位于程序目录之外。

用户已确认：

1. 使用原生 Windows MSI 安装包。
2. 内置更新入口，把“检查新版”“下载安装包”“安装更新”分成独立操作。
3. 安装包先下载到指定目录；稍后安装时直接读取已经下载的包，而不是重新下载。
4. Session 的存在不妨碍检查或下载。
5. 安装采取保守规则：只要还有任何打开的 Session，就不允许安装，明确要求用户先关闭所有 Session。

其中“任何 Session”指当前 Desktop 后端 Registry 中登记的全部 Session，覆盖所有 Project。运行、空闲、等待输入和 stopped 状态均不例外；不能用当前选中 Session、可见列表或 Pi 子进程数量代替这个判断。历史目录里尚未打开的 Pi 会话文件不属于此集合。

## 预期行为

### 检查新版

- 用户可以单独检查更新，看到当前版本、可用版本或检查失败原因。
- 检查不改变现有 Session、Project 选择、草稿和 Pi 执行状态。
- 检查本身不触发安装。自动检查的时机和频率尚未确认，不能从“内置更新”推导出定时轮询要求。

### 下载安装包

- 用户可以在有 Session 的情况下下载更新，不需要先停止工作。
- 下载操作与安装分离；下载完成不得自动关闭 Session、退出应用或启动安装器。
- 只有文件完整且通过可信校验后，才可以显示为“已下载、可安装”。中断或损坏的文件不能被误当成完成的下载。
- 本地文件路径由宿主决定，不由 renderer 提供。缓存位置和保留策略见 SHAPE 中的候选设计，不是本规范已锁定的路径要求。

### 安装已下载版本

- 界面明确显示本次要安装的本地版本。检查到更高版本时，不能把已下载版本悄悄解释成另一个版本。
- 安装读取本地 MSI 及其校验信息，不重新下载安装包，也不以重新请求远端 latest 作为安装的必要条件。
- 本地文件丢失或校验失败时，明确提示重新下载，不执行该文件。
- 有任何打开的 Session 时，拒绝安装，明确提示“请先关闭所有会话，再安装更新。”用户自行通过现有关闭入口处理；更新功能不提供隐式批量关闭。
- Project 切换、Session 失去前景、停止生成回答以及窗口隐藏到托盘，都不算关闭 Session。
- UI 的禁用状态只是提示。安装请求到达后端时，必须重新检查全部 Session。
- 已经发起、尚未建立 Session 的 New/Resume 也不能与安装穿插：先完成或由用户取消该操作，再安装。不能因为 Registry 暂时为空而让稍后的回调创建 Session。
- 获准安装后，不再接受新的 Session 创建/恢复；先保存 Desktop/Registry 元数据，再交给 MSI 执行更新。
- 保存失败时，不得继续当作正常更新退出。安装器启动失败或被用户取消时，不得谎报安装成功；具体恢复路径需要在 Windows 实验中验证并向用户说明。

### 数据与程序边界

- MSI 包含匹配的 Rust EXE、`backend.cjs` 和 `pi-extensions` 等运行资源，不能只替换其中一个组件。
- 安装/升级不得清理 FrostPi 的设置、Project/Session 索引或 Pi 历史。保持 `FROSTPI_DESKTOP_USER_DATA` 的既有语义。
- 不承诺更新后继续执行原来的 Pi 任务。所有 Session 必须由用户先关闭，不能借更新偷偷中止任务。
- 关闭 Session 时草稿、临时对话的处理仍由现有关闭行为负责。本次不引入草稿持久化或新的会话恢复机制。
- 新安装器的退出/重新启动必须与单实例和托盘行为协调，不能把“关窗只隐藏”当作允许替换程序的退出动作。

## 架构与质量约束

- 本次是 Desktop 功能。共享 ClientApp、SessionRegistry 和 Pi RPC 的协议/执行职责不扩展为软件更新系统；VS Code 开发不增加 MSI/Rust 构建前提。
- Node 后端是 Session 集合和 Session 准入的权威。Rust 壳拥有本地更新文件、可信校验及原生安装器的执行权。
- renderer 只提交有限更新动作、消费投影视图，不获得任意 URL 下载、文件路径、命令执行、密钥或原生 updater API。
- 安装器和需要在应用退出后继续运行的更新操作不得由 Node 派生。Node 位于 `KILL_ON_JOB_CLOSE` Job 中，应用退出会终止其后代。
- 正常退出和更新退出必须复用元数据收尾的所有者，不能各自复制一套 Registry/导航 flush 顺序。
- 不得为防安装竞态而全局串行化 agent turns。需要控制的是 Desktop 的 Session 准入和应用关闭阶段。
- 更新包必须有由应用信任的发行密钥验证的签名。下载包旁边的 SHA-256 不能单独替代发行者验签；Windows Authenticode 与此是不同机制。
- 下载后和安装前都要校验实际包内容；可写缓存目录不能被当成信任来源。更新流程不读取 Pi provider 凭证。
- 产品版本继续以 `apps/vscode/package.json` 为唯一来源，不引入独立 Desktop 版本。
- 版本清单只能在对应 MSI 与签名可用后发布，不能向客户端宣告尚未上传完整的 Desktop 版本。

## 范围边界

本次包含 MSI 安装/升级、独立检查/下载/安装操作、本地已下载包的管理、Session 安装门禁以及相应发布和验证适配。

本次不默认包含：

- 有 Session 时的后台强制安装，或自动替用户关闭 Session。
- 增量更新、断点续传、无限重试、常驻更新服务或自行编写文件树替换器。
- 自动回滚、跨数据格式降级或零中断升级保证。
- Node、Pi/OMP 的自动升级或新的凭证存储。
- 多平台、多架构、多更新渠道或自建更新服务器。
- 新增“关闭所有 Session”产品功能；现有关闭入口足以执行本次规则。

是否继续发布便携 ZIP 尚未决定；“采用 MSI 更新”不自动授权删除已有 ZIP 能力。现有已发版没有更新功能，用户需要先手动迁移到带更新功能的版本；不承诺旧版凭空获得自动更新。

## 验收场景与验证归属

Agent 负责客观验证，不把可自动完成的 Windows 验证转交用户：

| 场景 | 应观察到的结果 |
|---|---|
| 有运行或空闲 Session 时检查、下载 | 操作正常，Session、草稿与 Pi 工作不被打断 |
| 当前 Project 为空，另一个 Project 有 Session | 安装被拒绝，并提示关闭所有会话 |
| Session 为 stopped、未选中或等待输入 | 仍拒绝安装，不依赖“是否忙碌” |
| UI 曾显示可安装，随后又建立了 Session | 后端最终检查拒绝安装 |
| New/Resume 停在发现目录或 picker，Registry 暂时为空 | 安装不能越过该操作；不自动取消它 |
| 所有 Session 已关闭，安装获准后又到达创建请求 | 新请求被拒绝，没有新的 Pi 子进程出现 |
| 已下载后断网或远端发布了另一版本 | 仍可验证并使用本地指定版本，不重新下载或依赖 latest |
| 下载中断、MSI 丢失或内容/签名遭修改 | 不显示为可信的可安装包，错误明确可见 |
| 元数据保存失败 | 不以成功状态进入 MSI 安装 |
| 从较旧 MSI 升级到较新 MSI | 所有运行资源来自同一版本，设置和索引保留，应用可以启动 |
| MSI 安装失败或被取消 | 不显示成功；原程序可用性和恢复步骤有实际验证证据 |
| 升级后重新打开并 Resume 历史 | Project 信息和 Pi 历史未丢失，现有会话语义未改变 |

需要真实 Windows 上的两版本 MSI 验证，不能用 JS 单测、ZIP 解压验证或一次干净安装代替。安装目录、MSI 产品标识和测试 profile 必须隔离，不能升级或卸载用户正在使用的实例。GUI/打包证据绑定实际源码和安装包，不复用旧 ZIP 报告。

用户负责判断更新入口位置、操作文案、系统安装器提示和权限交互是否合适；这些观感与取舍不能由类型检查代替。

## 尚需确认或实测的事项

- UI 入口以及是否自动检查/自动下载。SHAPE 提议独立 Updates 面板，首版先提供显式操作，不把这一提议写成已确认需求。
- MSI 安装范围、权限提升、安装目录选择及升级标识；升级后是否自动重新打开应用。
- 缓存是否跨应用重启保留、一次保留多少安装包，以及清理时机。离线安装本地包是目标，但不推导出多版本仓库或自动回滚要求。
- MSI 成为主分发后，便携 ZIP 是否继续公开发布及其更新入口应如何呈现。
- 安装器启动失败/取消时的准确恢复行为，以及多 profile 进程共享同一安装目录时的处理边界。

以上事项未确定前，SHAPE 保持 draft；不能通过实现细节或 Agent 自行补写的规范替用户决定。
