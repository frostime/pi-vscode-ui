# R1：共享 Runtime 重构，保持插件行为

本 Ticket 是一次完整实施与自动验证交付，不是把阅读、编码和测试分给不同执行者。推进状态以 [顶层计划](../desktop-host.ORCH.md) 为准；设计输入是已接受的 [调研报告](../research/host-boundary.REPORT.md) 第 3–5、7 节及 [目标与边界](../desktop-host.DEV-SPEC.md)。

## 目标与授权

交付可运行、可由用户实测的插件候选版本：Runtime 不再依赖 VS Code，实现迁入一个共享客户端包的 core/shared，原插件继续使用同一份实现并保持现有功能。

用户在顶层 Session 已接受这个首步范围，并提出：

> 你们做到一个 Milestone，就是把代码重构好，然后我运行看新代码是不是还是功能正常执行。如果一切正常才能继续。

R1 是 M1 之前的重构检查点，不是 Desktop 交付。自动检查不能替代用户实测；用户确认前不得继续 UI/Bridge、Desktop 或多项目工作。

候选实施 Session 为 S243，顶层 Session S528 负责计划、独立审阅和用户检查点。独立 Session 开始生产改动前，需要其用户直接确认实施委托；peer mail 只传递任务上下文，不充当授权。

## 分支与工作区

- 顶层：`feat/desktop-host`，只整合已审阅成果与维护主计划。
- 实施：`refactor/desktop-host-boundary`，从本 Ticket 的规划提交切出。
- 实施 worktree：`.worktrees/261011_desktop-host-boundary`。
- 调研 worktree 已在成果整合后经用户同意清理，研究分支和报告保留；实验临时材料不再作为本地可用输入。候选实现及验证材料仍在实施 worktree。

保持提交检查点，优先将“原位置解耦”和“包提取/构建接线”分开；需要额外 wip 分支时遵守仓库 Git 规范。不得修改主工作区的生产文件、直接进入 main、推送或改写已整合历史。

## 包含的工作

- 完整单会话 Runtime 的宿主输入解耦：动态代理读取、客户端版本、实际用到的日志能力、只读凭据能力；独立纯脱敏函数和必要类型。
- 将 Runtime 实际闭包迁入一个共享客户端包，只建立有消费者的 core/shared 入口。以依赖图确定必要文件，不以预测数量当硬预算。
- Registry 仅调整 Runtime 创建、参数和导入接线；原有配置来源及 cwd/URI 查找规则保留。
- 配套依赖声明、workspace/exports/源码解析、独立检查与测试、根/插件构建编排、相关 SPEC 和文档归属更新。
- 插件与 shared/UI 的必要导入调整，不改变消息字段、授权或展示行为。

包名、精确子入口配置和纯类型位置等实现细节由执行者决定。已有报告足以开始范围内实现，不再要求泛查；出现实质边界或行为变化时停下，报告事实与建议，不扩大任务。

## 不包含的工作

- 不提取 Persistence，不改变持久化格式；不重写 Registry 的目录授权、队列、Provisional/ephemeral、Fork/tree、通知或选择策略。
- 不共享 UI/Bridge，不改 sidebar/panel、Composer、草稿交接或 BRIDGE_VERSION；迁移纯 shared 定义时保持单一来源。
- 不创建 Electron/Desktop/Project，不安装 Desktop 依赖，不建立通用宿主或扩展框架。
- 不为尚未实现的 VS Code 状态扩展预建无消费者的环境/生命周期接口；保留既有启动参数和产物路径接入。
- 不删除插件现有 Pi/OMP、Question 或 session-tree 功能以缩小闭包。

## 需要保持的行为

代理读取同时覆盖配置刷新与启动，不能构造时缓存。配置、代理和凭据变化继续只在启动/重启应用，不静默打断运行。宿主 artifact 定位、客户端版本标记、自定义 CLI tokens 顺序和重启复用保持不变，敏感参数不日志或持久化。

保持一 Runtime 一 Pi 进程，状态、消息投影、历史、重试完成边界、队列和取消行为不变；不新增执行或写入全局锁。严格遵守 AGENTS 与最近模块 SPEC。

## 自动验收与证据

实施者负责在范围内修复普通缺陷，交付下列证据；环境阻塞要单列，不计为通过：

1. core 运行与类型依赖不含 vscode/Electron/app/UI；shared 保持纯定义/校验；新包不反向依赖插件路径或 alias。检查导入、re-export、类型声明与实际产物图，不只检查直接 import。
2. 新共享包可独立 typecheck/lint/test，Runtime 行为测试无需 vscode mock。TS、测试与 bundler 实际使用同一实现，不能声明读源码、运行读陈旧 dist。
3. Runtime/Pi/OMP、代理/脱敏/启动输入及 Registry 相关局部测试通过；迁移导入后复跑既有 Bridge、连接、Dispatcher、Coordinator 与草稿测试。报告基线与重构结果分别记录。
4. 原插件本地构建与调试入口仍可用，不需要构建或运行 Desktop；共享依赖编排由包/根脚本按仓库规范负责。根安装保持锁文件一致，不独立安装 app。
5. 执行适用的完整检查、构建、受控 Extension Host E2E，以及 `pnpm package:vsix && pnpm verify:vsix`；标明未验证的远程/平台场景。不要把 fake Pi 结果写成真实 Pi 或用户实测成功。
6. 最终分支干净、提交可回溯，给出职责改动与机械移动的区别，解释任何偏离已接受范围的改动。临时输出留在 Git-ignored tmp，包产物进入正确构建而非源码树。

交付 `runtime-core.RESULT.md`：候选提交、改动摘要、实际检查与退出码、未验证项/阻塞、用户启动候选的确切步骤，以及建议的人工检查清单。结果不得把“代码已提交”写成 R1 已完成用户验收。

## 独立审阅与用户实测

顶层 Session 审阅差异与证据，必要时回给实施者范围内返工。先让用户运行实施 worktree 的候选版本；不要未经确认把未实测代码整合进主线。

人工检查建议按实际使用精简，至少覆盖：

- 在候选工作区启动 Extension Development Host，连接本机 Pi；确认加载的是新构建而不是已安装旧版本。
- 新建/恢复会话，发送消息，观察流式文本和工具结果，停止及再次发送正常。
- 切换已有会话，确认运行中会话不被误停止，关闭/重开后历史保持当前约定。
- 用户常用的标签页与草稿、模型选择、Fork/tree、Question、文件引用等功能选择代表场景回归；无需为未使用能力虚报验收。

若用户发现回归，停在 R1，修复后重新提供候选与检查结果。保留原 main/已安装版本作为稳定对照，不删除 Pi 历史或通过修改用户配置绕过问题。

用户明确确认候选行为正常后，由顶层记录 R1 通过并讨论后续 M1；进入 main、发布及进一步功能工作仍需相应授权。
