# R1 插件重构人工验收 SOP

本次只验收 VS Code 插件的行为保持，不测试 Desktop。按顺序完成核心用例，再检查自己常用的功能。预计需要 20–30 分钟，会产生少量模型调用费用。

候选自动验证见 [main-sync.RESULT.md](main-sync.RESULT.md)。人工结果交给 Agent 后，由 Agent 更新[主计划](../desktop-host.ORCH.md)；本文件不单独维护阶段进度。

## 1. 准备并确认运行对象

### 打开候选，而非主目录

在 VS Code **新窗口**打开：

```text
H:/SrcCode/playground/FrostPi/.worktrees/261011_desktop-host-boundary
```

主目录 `H:/SrcCode/playground/FrostPi` 尚未包含重构生产代码。在主目录按 F5 不算测试候选。也不需要安装候选 VSIX 或覆盖稳定插件。

在候选窗口的终端执行：

```bash
git branch --show-current
git rev-parse --short HEAD
git status --short
git merge-base --is-ancestor main feat/desktop-host; echo $?
git merge-base --is-ancestor main refactor/desktop-host-boundary; echo $?
```

- 分支应为 `refactor/desktop-host-boundary`，当前交付提交为 `acc25f2`。
- `git status --short` 应无输出；两个祖先检查均应输出 `0`。
- 如果提交已变化，或任一祖先检查非 `0`，先让 Agent 核对候选与证据，不直接套用旧验收结论。这里检查的是本地 main，不代表远端一定没有更新。

### 启动开发插件

1. 按 **F5**，选择 **Run FrostPi Extension**。启动配置会先执行 `pnpm build`。
2. 如果提示缺少依赖，在候选根目录执行 `pnpm install --frozen-lockfile`，成功后重试。构建失败则记录错误并暂停，不选择忽略错误继续启动。
3. 后续操作全部在新出现的 **Extension Development Host** 窗口进行。
4. 在这个窗口打开一个可信的本机测试项目。建议用无敏感数据的小目录；不要把包含多个关联 worktree 的 FrostPi 仓库作为首轮测试项目。
5. 打开 FrostPi，使用平时已配置好的真实 Pi 与模型。Pi 不在 PATH 时，使用 **FrostPi: Configure Pi Executable**，不要为本次验收重做账户配置。

开发窗口可能沿用已有 VS Code 配置及 Pi 历史。这不是隔离沙箱。下面的提示词不要求修改文件，但仍应查看工具参数，避免误操作。历史恢复请选择可用于测试的会话。

## 2. 核心用例

每项记录为 **通过 / 失败 / 阻塞 / 未测**。阻塞表示缺少环境或前置条件，不等于通过。只勾选实际完成且符合预期的项目。

### T01 新建会话与流式输出

1. 执行 **FrostPi: New Session**。若出现目录选择器，选择测试项目对应目录。
2. 发送：

   ```text
   本次测试标记是 R1-A-731。不要调用工具，不要修改文件。请用 8 个编号段落介绍代码审查，每段约 50 字。最后一行写 R1-A-731。
   ```

3. 观察输出过程；结束后发送：

   ```text
   不调用工具。只回复上一条消息指定的测试标记。
   ```

**通过标准：** 消息逐步出现，段落没有明显重复或丢失；结束后退出忙碌状态，能继续发送；第二次回复为 `R1-A-731`。将此会话记为 **A**。

### T02 工具结果与工具时长

在 A 中发送：

```text
请调用 bash 或 powershell 工具执行下面的命令，等它结束后回复结果。不要修改任何文件。如果没有这些工具，请明确说明。
node -e "setTimeout(()=>console.log('R1-TOOL-OK'),3000)"
```

**通过标准：** 能看到工具调用、命令参数及 `R1-TOOL-OK` 结果；运行时有计时变化，结束后显示合理的最终时长，不再持续增长。只对 `bash`、`powershell`、`codemode` 检查时长，不要求每种工具都有计时。

若模型未调用工具，或环境中没有 `node`，先记录阻塞；不要把纯文本回答当作工具测试通过。最终时长不必精确等于 3 秒。旧历史若未保存时长，也不要求凭空补出数值。

### T03 Stop 与停止后继续使用

1. 在 A 中发送：

   ```text
   请调用 bash 或 powershell 工具执行下面的命令，等它结束后再回答。不要修改文件。
   node -e "setTimeout(()=>console.log('R1-WAIT-DONE'),30000)"
   ```

2. 等工具卡片进入运行状态后，点击 **Stop**，不要等满 30 秒。
3. 停止完成后发送：

   ```text
   不调用工具，只回复 R1-STOP-OK。
   ```

**通过标准：** 当前回合停止，界面不长期卡在运行中；未完成工具不再显示为持续运行；新消息得到 `R1-STOP-OK`。停止不应清空已完成的历史。取消的工具不要求显示完整时长。

若命令在点击 Stop 前已完成，重试本项，不计为停止成功。

### T04 会话切换与后台运行

1. 新建会话 **B**，发送 `不要调用工具，只回复 R1-B-842。`，等待完成。A、B 都必须已发送过消息，避免把未提交的临时会话当成持久会话。
2. 切回 A，重新发送 T03 的 30 秒命令，这次**不点击 Stop**。
3. 工具运行时切到 B，发送 `不要调用工具，只回复本会话第一条消息要求的标记。`
4. 等待 A 的命令结束，再切回 A。

**通过标准：** B 回复 `R1-B-842`；A 在后台继续运行，回来后能看到 `R1-WAIT-DONE` 及工具结果。两边消息、工具卡片和忙碌状态不串会话，切换不会停止 A。

### T05 重启与恢复历史

1. 等 A 空闲，记录它的名称及最近几条消息。
2. 在 A 执行 **FrostPi: Restart Current Session**；如有确认，确认后等待恢复。
3. 检查 T02、T04 的工具结果和最近消息，再发送 `不调用工具，只回复本会话最早指定的测试标记。`。
4. 关闭 **Extension Development Host**，保留用于 F5 的源码窗口。从源码窗口再次按 F5，在新的开发窗口打开同一个测试项目。
5. 从会话列表选择 A；若未自动启动，按正常入口启动。另用 **FrostPi: Resume Existing Session** 恢复一份可测试的已有 Pi 历史，加载完成后发送简短消息。

**通过标准：** 重启和重新打开后能恢复正确会话；历史不变成空白，不出现明显重复或错位；A 的标记为 `R1-A-731`。新产生的工具结果恢复后仍可查看。已有 Pi 历史能加载并继续对话。

如果历史较大而出现显式加载入口，先完成加载再发送；不要把按需加载误判为丢失。没有可用旧历史时，单独记录“旧历史恢复未测”。

### T06 Provider usage

本项会查询真实服务商用量接口。使用已有配置即可，不为测试新增账户或分享凭据。

1. 点击侧边栏底部 **Usage**（位于 **Context** 左侧）。
2. 查看当前 Provider 的结果，点击 **Refresh** 再查询一次。
3. 关闭并重新打开面板；若有其他已配置 Provider，可切换一次，观察模型选择是否保持不变。

**通过标准：** 支持且可查询的 Provider 显示用量、余额或该服务支持的信息；刷新完成后不一直转圈。关闭、重开和切换不会清空对话或输入框，也不会替你切换 Pi 模型。

不支持的 Provider、无法取得凭据、网络失败应给出对应提示，不能显示成“用量为零”或伪装查询成功。仅验证了错误提示时，应记录“错误提示通过，成功查询未测”。不要以会话 token 或费用估算是否等于账户配额来判断正确性。

### T07 常用输入与布局

1. 输入中文和两行文本，使用 Enter 换行，再用发送按钮或 Ctrl+Enter 发送。
2. 查看前面生成的编号段落和工具卡片，检查展开、折叠及滚动。
3. 将侧栏收窄到约 280px；分别切换自己常用的明亮、深色、高对比度主题，打开 Usage 和输入框查看。

**通过标准：** 中文输入和换行正常；消息只发送一次；按钮仍可操作，内容不被横向裁掉。只记录实际检查过的主题。

## 3. 按使用习惯补测

下面不是要求启用全部功能。常用功能应补测；未使用或环境不具备的项目写明未测。

| 功能 | 操作 | 重点检查 |
|---|---|---|
| Session Tab | 将已有会话打开到编辑器标签页，在侧边栏与标签页之间切换 | 标签页不跟随侧边栏切到别的会话；草稿交接无明显丢失或重复；关闭标签页不停止后台回合。普通侧边栏草稿不承诺跨会话永久保存 |
| 文件引用 | 在测试文件中选择几行，用 `@Selection` 或 `@CurrentFile` 插入引用 | 输入框中的路径、行号正确；不要把引用当成插件自动读取了文件内容 |
| 图片 | 粘贴一张无敏感信息的小 PNG/JPEG/WebP，并发送给支持图片的模型 | 预览、移除、发送正常；模型不支持图片时明确报错 |
| 模型与 thinking | 空闲时切换一个已可用模型，发送短消息；检查 thinking 选项 | 模型切换生效，不出现该模型不支持的 thinking 级别 |
| Fork / 会话树 | 在专用测试会话中 Fork 一条已完成用户消息；再测试 Branch here / Switch branch | Fork 产生独立会话；树导航仍属于原会话；取消操作不破坏原历史或草稿 |
| Pi 交互 / question | 用已有 Pi extension 触发一次熟悉的输入请求，切换会话后再回来作答 | 请求属于原会话，不自动确认、不投递到别的会话。未启用 question 时无需为验收启用 |
| 代理与远程 | 若日常依赖代理、SSH、WSL 或容器，在相同环境重跑核心链路 | 修改代理不应中断现有回合；重启后才生效。远程 Pi 应在远程 Extension Host 环境中运行 |
