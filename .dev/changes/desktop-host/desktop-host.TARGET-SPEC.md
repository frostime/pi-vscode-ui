# Desktop 副产品：目标与质量标准

## 目的

现有 VS Code 插件已经适合日常使用，但零散项目仍需要在终端中多开 Pi。本 change 要复用已有的聊天与会话能力，提供无需打开 VS Code 就能独立使用的 Desktop App，方便在多个目录中并行使用 Pi。

**VS Code 插件是主产品，Desktop 是同步维护的副产品。** 不把项目迁成桌面优先，不另写一个客户端。交付既包括可用的 Desktop，也包括低成本维护两个产出的方式；只有一个能运行的桌面窗口，不足以达成目标。

阶段成果、对应提交和验证范围见同目录 `desktop-host.MILESTONES.md`。本文只记录目标与约束，不承担执行计划或验证日志的职责。

## 期望的产品效果

Desktop 使用本机已安装的 Pi，提供轻量的多 Project、多 Session GUI。对话是主体，现有 New/Resume、输入框、工具、模型和交互卡片继续复用；只增加必要的桌面导航和宿主适配，不内置 IDE，也不负责安装、升级 Pi、管理账号或接管 Pi 对话文件。

Project 是浏览及 New/Resume 的上下文。添加后立即选中，有会话时回到上次查看项，没有会话就显示空状态，不保留另一 Project 的对话，也不自动创建 Pi。聊天 Header 只列当前 Project 的已打开会话，磁盘历史仍通过 Resume 打开。Session 归属于发起 New/Resume 的 Project，即使实际工作目录在其他 git worktree；归属不靠 cwd 猜测。切换 Project 或前台 Session 不停止后台执行，不改变已有会话的 cwd、配置来源或输入请求归属，未发送草稿仍属于原 Session。

侧栏可调宽、隐藏和恢复；隐藏后仍有入口发现后台待输入。窄窗保持聊天和必要操作可用。导航布局变化不能靠重建聊天客户端或复制会话状态实现。

Desktop 的设置独立保存，沿用适用的 VS Code/FrostPi 原始 dot keys、类型、默认值和语义，不另做键名翻译或手抄默认值。首次可从 VS Code 默认用户配置导入 FrostPi 及实际依赖的设置；导入是可编辑预览，Save 后才生效，此后独立维护，不修改或持续同步 VS Code 设置。真实 Desktop 专属设置使用 `desktop.*`，Project 和窗口等元数据不混入用户设置。

正常关闭停止 Pi 并等待 Project 清单、会话索引和选中项落盘。重开按既有 `frostpi.session.startOnOpen` 规则，只启动选中的已保存会话；没有保存选中项时不自动启动另一条。Pi 继续拥有聊天历史，本阶段不跨应用重启恢复草稿、临时会话、输入请求或执行中任务，也不自动重发指令。凭据不写入普通配置或应用状态文件。

## 架构级质量

### 同一份客户端实现，两个不对等的宿主

客户端主体属于 `apps/` 下的 FrostPi 应用实现，不是通用 SDK。通用 UI、会话行为和消息契约只维护一份，由 VS Code 与 Desktop 消费。允许外层布局不同，不允许靠复制、重写或手工移植维持“双端相似”。

**以 VS Code 的环境、术语和既有行为为参考。** VS Code 层保持薄，绑定真实能力；Desktop 承担 adapter/translate 和专属 UI。不能为了 Desktop 降到最低公共能力，也不要求模拟整个 VS Code SDK。客户端实际需要的宿主能力通过集中 interface 声明和注入，不随意导入产品运行时。

通用会话规则留在共享客户端。Desktop 的 Project 归属、上次查看项、窗口和侧栏状态留在 Desktop，不扩成另一套会话管理器。确有需要时可补小的共享接口，但不能把 Project 模型或 Desktop 条件分支塞进共享实现，也不能改变插件的默认行为。缺失能力应明确隐藏、禁用或拒绝，不以成功的空实现掩盖不兼容。

浏览器 UI、Node 应用逻辑和纯消息契约保持环境边界。UI 不直接取得 Node、文件系统或进程权限；宿主操作经过受校验、按会话授权的桥。并行 Pi 的文件写入继续由 Pi 负责，不增加全局执行锁或文件写入拦截。

沿用现有 CSS、class、Codicons、`--vscode-*` 变量和 `--frost-*` 映射，不为共享化重造视觉语言。VS Code 提供真实 Webview 环境，Desktop 补齐相应变量、字体和资源；这不承诺兼容 VS Code Workbench 内部 DOM/SCSS 或完整主题扩展。

### 维护效果必须成立

| 开发中的改动 | 应有的维护效果 |
|---|---|
| 消息、工具展示、输入框等通用 UI 细节 | 改同一份实现，自然进入两个产出，不向 Desktop 手工移植 |
| VS Code 专属集成 | 可以只改插件，不要求 Desktop 跟做，也不限制插件发展 |
| 共享契约、宿主能力或会话行为 | 能明确找到需要检查和适配的 Desktop 入口，不静默分叉 |
| Desktop 专属窗口、导航或原生交互 | 适配复杂度留在 Desktop，不反向改变插件约定 |

这些效果由代码归属、依赖限制、类型和行为回归支撑，不依赖开发者记住两端全部细节。插件仍可独立开发、构建和使用；纯插件工作不以构建或启动 Desktop 为前提。

## 验收场景

- 一次通用 UI 修改进入两个真实产出，且不是两份代码手工同步；仅界面相似或原型可操作不算证明。
- 从 Desktop 为两个无关目录新建或恢复 Pi 并同时运行。切到空 Project 不显示另一 Project 的对话；切回能继续原会话和草稿，待输入请求始终回到原 Pi。
- 在共享实现上验证真实 Pi 的发送、停止、历史恢复和阻塞输入；区分共享 Runtime、受控 GUI 与真实 Pi GUI 的证据，不相互代替。
- 正常关闭和重开符合保存、启动及不重放规则；插件原有会话、工作区、标签页与主题行为保持正常。Desktop 不支持的宿主能力可被识别。

## 本阶段范围

当前交付是未签名的 Windows x64 免安装 ZIP，不包含后台常驻、跨进程状态合并或掉电恢复保证。其他平台、安装器、跨重启草稿恢复和主题导入另行决定，不是本阶段的完成前提。局部界面的后续改良和未决事项记录在 MILESTONES 中，不自动转成新的顶层需求。
