# Desktop 副产品：目标与质量标准

## 目的

现有 VS Code 插件已经顺手，但零散项目仍需要在终端中多开 Pi。要复用这些已有优势，提供一个可独立使用的 Desktop App，替代 herdr／终端中的多项目、多 Pi 使用方式。

**VS Code 插件是主产品，Desktop 是同步维护的副产品。不是把项目迁成桌面优先，也不是另写一个客户端。**

## 期望的产品效果

- Desktop 使用本机已安装的 Pi，无需打开 VS Code。不负责安装、升级 Pi，不接管 Pi 的账号配置或对话文件。
- **多 Project 是核心功能。** 在一个 App 中保存、打开不同目录，为各 Project 新建或恢复多个 Pi，并行运行。
- 对话是主体，项目导航从简，默认显示全部已打开的 Pi。切换 Project 或前台 Pi 不停止其他 Pi，不改变已有会话的 cwd、配置来源或输入请求归属。
- 保留现有插件已经顺手的聊天与会话能力，包括现有 New/Resume、输入框、工具、模型和交互卡片；不另造会话管理流程，不内置 IDE。

## 架构方向

客户端主体归入 `apps/`，承载 FrostPi 的共享应用实现，而不是通用 SDK。VS Code 与 Desktop 消费同一份通用 UI、会话行为和消息契约。允许外层布局不同，不允许靠复制、重写或手工同步实现“双端相似”。

**以 VS Code 的环境、术语和既有行为为标准，不追求两个宿主对等。** VS Code 层保持薄，尽量绑定、透传真实能力；Desktop 承担 adapter/translate 和必要的专属 UI。不能为求最低公共能力而限制插件发展，也不承诺兼容整个 VS Code SDK。

- 用集中定义的宿主 interface 声明客户端实际需要的能力，通过装配注入。共享客户端不得随意导入 `vscode`；真实 API 访问留在 VS Code 层。接口可沿用 VS Code 的术语和适合的 API 形状，不另造中立平台语言。
- 通用会话规则与 UI 保持单一实现；目录来源、配置、存储、原生交互和编辑器集成由宿主提供。Desktop 的 Project 管理、窗口和目录导航留在 Desktop。
- 不支持的宿主能力须明确隐藏、禁用或报错，不能空实现后返回成功。明确依赖 VS Code 的设置取值，如代理模式 `vscode`，可在 Desktop 声明不兼容。
- 浏览器 UI、Node 应用逻辑和纯消息契约保持环境边界。UI 不直接获得 Node、文件系统或进程能力；两端继续使用受校验、按会话授权的消息桥。

## 设置与主题

Desktop 使用独立配置存储，但沿用适用的 VS Code 设置键、类型、默认值、取值和作用域。设置定义只维护一份。首次导入仅取 VS Code 默认用户配置中的 FrostPi 设置及实际依赖的设置，作为 Desktop 默认配置，不导入 Project/Remote 覆盖或当前窗口合成配置；此后独立维护，不修改或持续同步 VS Code 设置。Desktop 专属设置可独立命名；Project 列表、窗口和会话元数据属于应用状态，凭据不写入普通配置文件。

保留现有 CSS、class、Codicons、`--vscode-*` 变量及现有 `--frost-*` 映射。VS Code 提供真实 Webview 主题环境；Desktop 补齐同形的变量、字体和资源。不因共享化重写视觉体系，也不扩大为对 VS Code 内部 Workbench DOM/SCSS 的兼容承诺。

导入 VS Code 主题是未来可扩展方向，不是本轮首版的完成条件；完整主题继承、语法着色兼容不自动纳入范围。

## 架构级质量要求

| 开发中的改动 | 应有的维护效果 |
|---|---|
| 消息、工具展示、输入框等通用 UI 细节 | 改一处自然进入两个产出，不需要向 Desktop 移植 |
| VS Code 专属集成 | 可以只改插件；包括未来向 Pi 提供编辑器状态的扩展 |
| 共享契约、宿主 interface 或会话行为 | 类型、依赖和兼容检查能明确暴露 Desktop 是否需要适配，不能默默分叉 |
| Desktop 专属窗口、目录入口等 | 调整留在 Desktop，不反过来改变插件既有约定 |

这些边界必须由代码归属、依赖限制和检查支撑，不能靠开发者熟悉两端实现。插件仍可独立开发、构建和使用，本地流程不要求运行 Desktop，已有行为不因共享化退化。

## 完成的证据

- 实际证明一次通用 UI 修改进入两个产出；仅两张相似的界面、原型或插件测试通过不算完成。
- 在共享实现上跑通真实 Pi 的发送、停止、历史恢复和阻塞输入。
- 两个无关目录的 Pi 同时运行；切换 Project/Pi 不停止后台任务，草稿、历史和输入请求不串会话。
- 插件的原有会话、工作区、标签页与主题行为保持正常；Desktop 不支持的能力可被明确识别。

## 尚未决定

配置文件的跨平台位置、关闭/重开恢复、退出后是否继续后台运行、发布平台，以及 Header 与目录导航的具体组合仍需按实际取舍确认。草稿不得在前台切换时丢失，但其是否跨应用重启保存尚未决定。
