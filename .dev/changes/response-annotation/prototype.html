· ready prototype
我希望在 FrostPi 中引入类似的批注工具，但不要过度侵入现有交互。

我的建议是：不要让普通文本选择自动触发批注，而是在完成的回复旁提供一个明确的 Annotate 操作。

为什么使用明确入口

会话中的文本选择通常还承担复制、阅读和打开链接等用途。自动弹出编辑器会让一个原本安静的动作带上额外副作用。

只有在用户进入审阅工作台之后，选择文本才表示“我要针对这段内容写批注”。

最终生成的内容不会成为新的协议对象，而只是追加到 Composer 的普通文本。用户仍然可以修改它，并决定何时发送。

  • 不自动发送 prompt；
  • 不修改 Pi RPC；
  • 不在普通对话中保留永久高亮；
  • 批注来源是这条回复的原始 Markdown 文本。
