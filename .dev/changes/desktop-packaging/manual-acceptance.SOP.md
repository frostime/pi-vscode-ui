# 本次 Desktop 排查的手工验收 SOP

本文件是 `desktop-packaging` change 的临时排查材料，不是长期项目测试规范。

预计 5–10 分钟。请在可操作的 Windows 桌面上测试。

这个流程使用**当前 ZIP 的实际程序**，但创建独立临时数据和两个测试项目。它使用受控假 Pi，不读取你的日常 Pi 配置，不调用模型，不产生模型费用，也不修改正式 FrostPi profile。普通开发启动仍然共用正常 Pi 环境；这里的完全临时隔离只用于验收。

## 1. 启动

在仓库根目录打开 PowerShell，运行：

```powershell
pnpm test:desktop:manual
```

不要先重新打包。命令会检查 ZIP 的文件清单和哈希，打印本次 ZIP 的 SHA-256，然后打开测试窗口。记下那一行 SHA-256。测试期间保留这个终端。

如果 ZIP 缺失、校验失败或 Windows 阻止启动，停止并把提示发给我。不需要关闭安全软件或修改系统设置。

## 2. 按顺序检查

| 编号 | 你要做什么 | 应当看到什么 |
|---|---|---|
| 1 发送 | 选择 `project-a`，如有 `New session` 就点它。输入 `hello` 并点击发送。 | 对话出现 `hello`，随后出现固定回复 `E2E response`。 |
| 2 隐藏 | 发送 `stream-084`。看到 Stop 按钮后，在输入框写 `保留这段草稿`，不要发送。点击窗口右上角 ×；首次提示说明留在托盘时确认它。 | 窗口消失，但终端没有打印程序退出。这个测试任务会一直运行，直到你停止或退出。 |
| 3 恢复 | 查看任务栏右下角。若看不到 FrostPi 图标，先点 **显示隐藏的图标（小箭头）**。左键点击真实的 FrostPi 图标。 | 同一个窗口恢复，草稿仍是 `保留这段草稿`，Stop 按钮仍在。请记录图标是在外面还是隐藏区。 |
| 4 Show 菜单 | 再点 × 隐藏窗口。找到 FrostPi 图标并右键，点击 `Show FrostPi`。 | 菜单包含 `Show FrostPi` 和 `Exit`；窗口恢复，草稿和运行状态保持。 |
| 5 取消退出 | 右键 FrostPi 托盘图标，选 `Exit`。在 `Exit FrostPi?` 对话框点 `Keep running`。 | 窗口保留，任务没有被停止，草稿没有丢失。 |
| 6 并发与 Stop | 保持 A 的任务运行。切到 `project-b`，如有需要点 `New session`，发送 `hello`。再切回 A，点击 Stop。 | B 能收到 `E2E response`，不必等 A；回到 A 后草稿仍在，Stop 能停止任务。 |
| 7 真正退出 | 切换一次右上角明暗主题按钮。清空草稿，再发送一次 `stream-084`；从托盘选 `Exit`，这次在确认框点 `Exit`。 | 程序真正关闭，终端打印程序已退出。没有要求保存草稿；退出后不保证恢复未发送内容。 |

任一步失败，就记下编号和现象，不必反复尝试到通过。若窗口藏起来后找不到图标，也请直接报告，**不要按进程名批量结束 Node/Pi**。

## 3. 重开检查

确认上一个测试程序已经退出，再在同一仓库运行：

```powershell
pnpm test:desktop:manual --reopen
```

应当恢复刚才的两个测试项目和主题。选择此前会话，检查能看到已保存的 `hello` / `E2E response`。这一项记为 **8 重开**。最后从托盘 `Exit` 退出；如果还有任务，确认退出。

`--reopen` 只使用上一次手测的临时 profile，并要求 ZIP 哈希相同。如果提示 ZIP 已改变或临时 profile 已丢失，请停止报告，不要把两轮结果合在一起。

## 结果边界

这个命令只准备并启动手测环境，**不会生成“GUI 已通过”的自动化报告，也不会发布任何东西**。我会按 ZIP 哈希记录你实际完成的检查，并保留自动化失败记录。手测通过不等于真实模型、全部原生文件对话框、32 MiB 边界或崩溃回收都通过。正式发布的人工放行流程若要替代现有自动门槛，需要另行明确；当前自动发布仍然失败关闭。
