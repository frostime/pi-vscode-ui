**建议：优先纳入。** 这是现有缺陷的修复，不新增生命周期操作。`f22119b9` 在 `15bb0ec` 上通过独立正确性与维护性复审；与 #33 一起试合后，Runtime、轮次投影及会话命令共 99 项定向测试通过。Stop / Restart 会拒绝旧 child 的待处理 RPC；同一批已返回的快照仍是原有边界，不由本 PR 处理。

`SessionRuntime.ts` 每收到一次 `agent_start` 就增加计数。前一轮结束后并发读取状态、统计和命令；如果返回前计数已变，不再用旧状态覆盖运行中的下一轮。同步更新了生命周期 SPEC。假 Pi 的回归测试确实制造了「先返回空闲，下一轮启动，再返回命令」的时序；合成快照定向测试通过。

正确性：对同一进程内的目标竞态，修复直接，且统计和命令没必要随轮次一起丢弃。给已经存在的 `#refreshAfterSettled` 加一个局部时序检查，比另起队列或刷新流程容易维护。相邻的 compaction 刷新在写回前会确认 `api === this.#api`，settle 刷新仍没有这道旧进程保护。该缺口早于 #24；#13 增加显式 Stop / Restart 后应验证旧响应不写到新进程，与本 PR 的轮次计数是两个边界。

组合：三方实际只冲突 CHANGELOG。#13 用运行态来选忙时 Fork 的路径，也用它阻挡忙时 `/new`；#24 保护这两个判断，不解决 Fork 误删，也不保证旧会话名永不覆盖新的实时改名。
