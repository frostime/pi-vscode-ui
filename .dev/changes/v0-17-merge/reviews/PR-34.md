## 做了什么

把 VS Code manifest 的 `frostpi.composer.fileMentions.followSymlinks` 默认值改为 `false`，同步 shared 配置定义和默认值生成文件，并更新配置测试。VS Code 与 Desktop 共用该设置；显式设为 `true` 的用户仍会传入 `fd --follow`。没有改搜索实现。

## 正确性与维护性

配置源和生成文件一致，沿用现有配置边界。需要纠正的是行为表述：`WorkspaceFileSearch.ts:65,164–168` 用会跟随链接的 `statSync` 判断目录，`fdArgs.ts:27–42` 会把显式目录前缀用作搜索起点。用真实 `WorkspaceFileSearch`、Windows junction 和 fd 10.4.2 验证：工作区根目录不带 `--follow` 找不到目标文件；带该参数能找到；以链接目录作为起点时，不带参数也能找到。**它限制普通递归遍历，不是禁止显式访问链接目录，也不是访问控制。** 若要强禁，另开范围，不把路径校验塞进本 PR。
