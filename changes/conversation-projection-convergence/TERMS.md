# 术语约定

本文约束本 change 中的讨论、规格、计划和交接文档。面向用户时优先使用中文术语；只有在对应源码名称时，才在第一次出现后附上英文或代码标识。

## 用户层概念

| 固定术语 | 含义 | 必要时对应的源码词 |
|---|---|---|
| 用户回合 | 一次用户请求及其后续工作，在 FrostPi 中显示为一个整体。 | visual turn |
| 执行尝试 | Pi 向模型请求一次结果。自动重试会产生新的执行尝试。 | attempt |
| 会话记录 | Pi 写入磁盘、重新加载时可以读取的消息或边界记录。 | session entry |
| 实时信号 | Pi 运行过程中发出的状态通知；其中一部分不会写入会话记录。 | live event |
| 自动继续 | Pi 核心在没有新用户请求时，因自动重试或上下文压缩而继续执行。 | retry / continuation |
| Pi 扩展 | 加载到 Pi 进程中的扩展程序；可以注册工具、命令或通过 Pi 接口发起消息。它不是 FrostPi。 | Pi extension |
| FrostPi | 当前 VS Code 扩展和 Pi RPC 客户端；负责把 Pi 的消息与状态显示在 GUI 中。 | FrostPi |
| 来源信息 | 说明一次执行为什么开始、属于哪个用户回合的持久化信息。 | provenance；面向用户时不使用该英文词 |

## 技术讨论概念

| 固定术语 | 含义 | 必要时对应的源码词 |
|---|---|---|
| 当前路径 | Pi 当前选中的、从会话根节点到末端节点的有序会话记录。 | active path |
| 历史投影 | 仅根据会话记录构造稳定会话界面的过程和结果。 | persisted projection |
| 临时界面状态 | 尚未由会话记录确认的用户请求、流式回复、工具状态和重试提示。 | live state |
| 对账 | 将临时界面状态与新读取的会话记录合并，并消除临时副本。 | reconciliation |
| 增量对账 | 当前路径只在末尾追加时，仅处理新增记录并与现有界面对账。 | incremental reconciliation |
| 全量重建 | 清空现有历史投影，再根据完整当前路径重新构造。 | full replacement |
| 消息身份 | 用来判断实时消息与会话记录是否代表同一条 Pi 消息的关联依据。 | identity |
| 消息位置 | 一条消息所属的用户回合及其在回合内的顺序。 | location |
| 消息迁移 | 同一消息的位置改变时，从旧位置移除并放入新位置。 | relocation |
| 结果收敛 | 增量对账完成后，与全量重建得到相同的稳定内容、顺序、归属和状态。 | convergence |

## 写作规则

1. 同一概念始终使用表中的同一中文术语，不在“消息记录、持久项、历史节点”等近义表达之间切换。
2. `agent_start`、`agent_settled`、`auto_retry_start` 等协议字段保持源码拼写，并在首次出现时解释其用户含义。
3. 不单独使用 `canonical`、`overlay`、`provenance` 等英文架构词。确有必要时，先说明完整中文概念，再附源码或行业名称。
4. 图示先说明用户看到什么，再说明会话记录保存什么，最后说明代码如何处理。
5. 产品选择使用用户层概念；类、状态字段和算法选择留在技术方案章节，不能要求用户理解实现术语后才能作出产品判断。
